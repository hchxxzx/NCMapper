## 6. Detailed Mapping Scenarios

### 6.1 Basic Mapping

NCMapper’s basic mapping follows the **“name-matching-by-default”** principle: properties with **identical names** (case-insensitive) between source and target types are automatically mapped without requiring any additional attributes.

#### Matching Rules

Property matching uses `StringComparer.OrdinalIgnoreCase`, meaning `UserName`, `username`, and `USERNAME` are treated as the same property. Matching searches upward along the inheritance chain; a subclass property shadows (overrides) a base-class property with the same name (shadow property support is enabled).

**Properties participating in matching must satisfy all of the following conditions**:

| Condition | Description |
| --------- | ----------- |
| Not an indexer | `GetIndexParameters().Length == 0` |
| Source property has a getter | `CanRead == true` |
| Target property has a setter | `CanWrite == true` (init-only properties are supported only in the object-initializer path generated by the source generator) |
| Not marked with `[MapIgnore]` | Direction-aware ignore control |
| Public visibility | Non-`public` members are excluded from mapping |

```csharp
public class UserEntity
{
    public int Id { get; set; }
    public string Name { get; set; }
    public DateTime CreatedAt { get; set; }
    internal string Secret { get; set; }          // ✗ Not public → excluded
    public string ReadOnly => "computed";          // ✗ No setter → no match on target side
}

[MapFrom(typeof(UserEntity))]
public class UserDto
{
    public int Id { get; set; }                   // ✓ Same name & type → direct assignment
    public string name { get; set; }              // ✓ Case-insensitive match for Name
    public DateTime CreatedAt { get; set; }       // ✓ Same name & type
}
```

#### Type Compatibility Dispatch

After successful name-based property matching, assignment behavior is determined by the following priority chain:

```
1. [Convert] custom converter     → Highest priority (see Convert Conversion)
2. Identical types (srcType == tgtType)    → Direct assignment: dst.Prop = src.Prop
3. Implicit numeric conversions (C# spec 10.3.2)     → Explicit cast: dst.Prop = (long)src.Prop
4. Nullable → Non-nullable         → dst.Prop = src.Prop.HasValue ? src.Prop.Value : default
5. Non-nullable → Nullable         → dst.Prop = new int?(src.Prop)
6. Nested class (different types)            → Recursive mapping (see Nested Object Mapping)
7. Collection types                       → Collection mapping (see Callbacks and Collections)
8. Dictionary types                       → Dictionary mapping
9. Enum conversion                       → `switch` expression (see Constructors and Record Types)
10. `TypeConvertHelper` fallback         → Runtime conversion (string ↔ primitives, `IConvertible`, etc.)
```

**Implicit numeric conversions** rely on a precomputed lookup table aligned with section 10.3.2 of the C# Language Specification, covering all valid widening paths:  
`byte/sbyte → short/ushort → int/uint → long/ulong → float → double → decimal`.  
Enumerations are explicitly excluded from implicit conversion (they follow the dedicated enum-conversion path).

The **`TypeConvertHelper` fallback path** handles conversions that cannot be resolved at compile time by the source generator:

| Conversion | Implementation |
| ---------- | -------------- |
| `source is TTarget` | Direct return (already target type or subtype) |
| `string` → primitive | `Convert.ChangeType` |
| Value-type ↔ value-type | `IConvertible.ChangeType` |
| `enum` → `string` | `source.ToString()` |
| `string` → `enum` | `Enum.Parse(ignoreCase: true)` |
| Numeric → `enum` | `Enum.ToObject` (**excluding** `float`/`double` — see reference table ④ below) |
| Any → `string` | `source.ToString()` |
| Any → `Guid` | `Guid.TryParse` |
| All others fail | Throws `MapException` |

> Unsupported: **No automatic conversion between `string` ↔ `byte[]`** (`byte[]` does not implement `IConvertible`; JSON/text semantics require explicit declaration). For Base64 round-trip, use a `[Convert]`-attributed custom converter.

#### Automatic Conversion Type Reference Table

The following table fully enumerates all type-pair combinations eligible for automatic conversion when source and target properties share the same name (union of compile-time resolution criteria and runtime `TypeConvertHelper` capabilities).

**① Direct Assignment (Identical Types)**

| Source Type | Target Type | Implementation |
| ----------- | ----------- | -------------- |
| Any type `T` | Same `T` (including subtypes) | `dst.Prop = src.Prop` |

**② Implicit Numeric Widening** (Exact mirror of C# spec 10.3.2)

| Source Type | Automatically Convertible To |
| ----------- | ---------------------------- |
| `byte` | `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `float`, `double`, `decimal` |
| `sbyte` | `short`, `int`, `long`, `float`, `double`, `decimal` |
| `short` | `int`, `long`, `float`, `double`, `decimal` |
| `ushort` | `int`, `uint`, `long`, `ulong`, `float`, `double`, `decimal` |
| `int` | `long`, `float`, `double`, `decimal` |
| `uint` | `long`, `ulong`, `float`, `double`, `decimal` |
| `long` | `float`, `double`, `decimal` |
| `ulong` | `float`, `double`, `decimal` |
| `char` | `ushort`, `int`, `uint`, `long`, `ulong`, `float`, `double`, `decimal` |
| `float` | `double` |

**③ Nullable Types (`Nullable<T>`)**

| Source Type | Target Type | Notes |
| ----------- | ----------- | ------- |
| `T?` | `T` | `HasValue ? Value : default` |
| `T` | `T?` | `new T?(src)` |
| Numeric-family `A?` | Numeric-family `B?` | Underlying types belong to numeric family (includes `bool`, `char`) → e.g., `int? → long?` |

**④ Enum Conversions**

| Source Type | Target Type | Implementation |
| ----------- | ----------- | -------------- |
| `enum` | `enum` | Direct cast |
| `enum` | `string` | `source.ToString()` |
| `string` | `enum` | `Enum.Parse(ignoreCase: true)` |
| `enum` | Numeric type | Underlying numeric value via `Convert.ChangeType` |
| Numeric type (**excluding** `float`/`double`) | `enum` | `Enum.ToObject` |

**⑤ `string` ↔ `IConvertible` Value Types**

| Source Type | Target Type | Implementation |
| ----------- | ----------- | -------------- |
| `string` | Numeric types (`sbyte`…`decimal`, 11 total) | `Convert.ChangeType` + `InvariantCulture` |
| `string` | `bool`, `char` | Same as above |
| `string` | `DateTime` | Same as above |
| `string` | `Guid` | `Guid.TryParse` |
| Numeric types, `bool`, `char`, `DateTime`, `Guid`, `enum` | `string` | `ToString()` / `Convert.ChangeType` |

**⑥ Numeric-Family ↔ Numeric-Family (Explicit Narrowing)**

| Source Type | Target Type | Notes |
| ----------- | ----------- | ------- |
| Any of: `sbyte`, `byte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `float`, `double`, `decimal`, `bool`, `char` | Another type in the same family | Includes narrowing: `long→int`, `double→int`, `bool↔numeric`, `char↔numeric` |

**⑦ Structural Mapping (Automatic Recursion, *Not* “Type Conversion”)**

| Category | Source Type | Target Type | Notes |
| -------- | ----------- | ----------- | ------- |
| Nested class | Any non-generic, non-string, non-delegate `class` | Another `class` | Recursive per-property mapping |
| Collection | `List<T>`, `T[]`, `IEnumerable<T>`, etc. | Any collection shape | Element-wise recursive conversion (e.g., `List<A> → List<B>`) |
| Dictionary | `IDictionary`, `IReadOnlyDictionary`, etc. | Dictionary shape | Key/value pairs converted individually |
| List → Dictionary | `List<T>`, arrays | Dictionary shape | Controlled path (excludes `string` sources) |

#### Source Generator Code Generation

The source generator emits different assignment code based on type compatibility:

```csharp
// Identical types → direct assignment
dst.Id = src.Id;

// Implicit conversion → explicit cast
dst.LongValue = (long)src.IntValue;

// Nullable → Non-nullable
dst.Age = src.Age.HasValue ? src.Age.Value : default(int);

// Non-nullable → Nullable
dst.Score = new int?(src.Score);

// TypeConvertHelper fallback (comment inserted before generated code)
// fallback to runtime: TypeConvertHelper.ConvertValue<string, int>(src.Code)
dst.Code = NCMapper.TypeConvertHelper.ConvertValue<string, int>(src.Code)!;
```

When *all* properties are either **identical-type assignments** or **implicit conversions**, the source generator uses **object initializer syntax** (`new T { Prop1 = ..., Prop2 = ... }`) for optimal JIT optimization. Any complex mapping (nested objects, collections, enums, or `[Convert]`) falls back to line-by-line assignment.

#### Behavior for Unmatched Properties

| Engine | Behavior |
|--------|----------|
| Source Generator | Compile-time diagnostics: **NCMAP006** (Warning: target property has no matching source) / **NCMAP007** (Info: source property has no matching target) |
| Runtime | Silently skipped; target property retains its default value; no diagnostic output |

```csharp
[MapFrom(typeof(UserEntity))]
public class UserDto
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string NickName { get; set; }   // ⚠️ NCMAP006: No 'NickName' in source → remains null
}
// UserEntity.CreatedAt has no corresponding target property → ℹ️ NCMAP007
```

> Use `Mapper.Validate()` to detect all unmatched properties in bulk at runtime (see [Mapping Validation](../validation.md)).
