## 12. Mapping Validation

After mapping rules are declared, issues such as mismatched property names, incompatible types, or missing attributes often remain undetected until runtime. `Mapper.Validate()` scans all `[MapFrom]` mapping pairs at runtime, checking each property individually for correct mappability, and outputs an OK / Warn / Error report—enabling developers to proactively identify configuration errors instead of waiting for runtime failures. The validation result aggregates two components: (1) runtime reflection-based scanning, and (2) compile-time validation delegates generated by the source generator (registered via `RegisterGeneratedValidate`, covering all diagnostics NCMAP001–034 [excluding NCMAP004]). These results are merged and deduplicated before producing a unified report.

**Validation message language**: Report rows, summary prefixes, detail items, `PrintReport` headers and totals, and downgrade-reason row prefixes switch according to `CurrentUICulture` (defaulting to Chinese for `zh-CN`, English for `en-US`, e.g., `⚠️ Src → Dst: 3/5 properties mapped, 1 unmapped: ...`). In contrast, validation messages embedded in generated code by the source generator are fixed in English (hardcoded at compile time and unaffected by runtime culture—thus, mixed-language output may occur in `zh` environments, e.g., outer UI in Chinese + inner generated messages in English; this behavior is by design).

### 12.2 Validation Levels

| Level | Meaning                                      |
|-------|----------------------------------------------|
| OK    | All properties can be correctly mapped         |
| Warn  | Some properties are unmapped or have type mismatches |
| Error | Missing `[MapFrom]` annotation or no valid mapping available |

**Typical usage scenarios**—

| Scenario           | Description                                                  |
|--------------------|--------------------------------------------------------------|
| Startup validation | Call `ValidateOrThrow()` in `Program.cs`; application startup fails immediately on any configuration error |
| CI pipeline integration | Call `Validate()` in tests; CI fails if mapping configuration is invalid |
| Post-refactoring validation | Run validation after modifying DTO/Entity properties to confirm mappings remain correct |
| Pre-deployment check | Run `PrintReport` before deployment to inspect all Warn/Error entries |

```csharp
// Startup validation — blocks startup on any configuration error
builder.Services.AddNCMapper();
Mapper.ValidateOrThrow();  // Throws exception on any Error-level issue, causing startup failure

// Full report output in CI
var results = Mapper.Validate();
MapValidator.PrintReport(results, showOk: true);
```
