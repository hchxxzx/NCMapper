## 4. Core API

### 4.1 Mapping Entry Points

| Method                              | Signature                                                       | Description                           |
| ----------------------------------- | --------------------------------------------------------------- | ------------------------------------- |
| `Map<TSource>`                    | `(TSource, Action?) → TSource?`                                 | Shallow copy within the same type        |
| `Map<TSource,TTarget>`            | `(TSource, Action?) → TTarget?`                                 | Cross-type mapping                      |
| `Map<TSource,TTarget>`            | `(TSource, TTarget, Action?)`                                   | Update an existing target object         |
| `MapList<TTarget>`                | `(IEnumerable, Action?) → List<TTarget>?`                       | List mapping within the same type       |
| `MapList<TSource,TTarget>`        | `(IEnumerable<TSource>, Action?) → List<TTarget>?`              | Cross-type list mapping                 |
| `Compose<TTarget>`                | `(params object[]) → TTarget?`                                  | Multi-source composition                |
| `Compose<TTarget>`                | `(Action<TTarget>?, params object[]) → TTarget?`               | Multi-source composition + callback     |
| `ComposeList<TTarget>`            | `(params object[][]) → List<TTarget>?`                          | Batch multi-source composition          |
| `ComposeList<TTarget>`            | `(Action<TTarget>?, params object[][]) → List<TTarget>?`       | Batch composition + callback            |
| `DeepCopy<T>`                     | `(T) → T?`                                                      | Full deep copy within the same type      |
| `DeepCopy<T>`                     | `(T, Action<T,T>?) → T?`                                        | Deep copy within the same type + callback |
| `DeepCopy<TSource,TTarget>`       | `(TSource) → TTarget?`                                          | Cross-type deep copy (delegated to `Map`) |
| `DeepCopy<TSource,TTarget>`       | `(TSource, Action<TSource,TTarget>?) → TTarget?`               | Cross-type deep copy + callback         |
| `Validate()`                      | `() → List<MapValidationResult>`                                | Validate all registered mappings         |
| `ValidateOrThrow()`               | `() → void`                                                     | Throw exception if validation fails      |
| `HasGenerated<TSource,TTarget>`   | `() → bool`                                                     | Check whether a source generator is registered for the given type pair |
| `HasGeneratedDeepCopy<T>`         | `() → bool`                                                     | Check whether deep-copy generation is registered for the given type |
| `ClearGenerated()`                | `()`                                                            | Clear all source-generator delegates     |
| `ClearCache()`                    | `()`                                                            | Clear all runtime caches                 |
| `ResetMetrics()`                  | `()`                                                            | Reset performance metrics                |
| `src.MapToTarget()`               | Extension method                                                  | Generated by source generators; shares the same mapping logic as `Mapper.Map`. |

> **Note**: Methods prefixed with `Register*`, `Clear*`, or `Has*` are annotated with `[EditorBrowsable(Never)]` and are invisible in IntelliSense; they are intended for internal use by source generators only.

### 4.2 Source Generator Registration Methods

Source generators automatically invoke the following methods at compile time to register delegates. Users must *not* call them manually:

| Method                                   | Description                             |
| ---------------------------------------- | --------------------------------------- |
| `RegisterGeneratedCore<TS,TT>`         | Register core mapping delegate (no `Action` hot path) |
| `RegisterGenerated<TS,TT>`             | Register mapping delegate with `Action` support |
| `RegisterGeneratedList<TS,TT>`         | Register list-mapping delegate           |
| `RegisterGeneratedUpdate<TS,TT>`       | Register delegate for updating existing objects |
| `RegisterGeneratedDeepCopy<T>`         | Register deep-copy delegate              |
| `RegisterGeneratedCompose<TT>`         | Register multi-source composition delegate |
| `RegisterGeneratedValidate`            | Register compile-time validation delegate |
| `RegisterGeneratedConfig`              | Register globally generated mapping configuration (e.g., injecting `[MapDefaults]` per assembly) |

### 4.3 Runtime Controls

| Property                  | Type         | Default Value | Description                                   |
| ------------------------- | ------------ | :-----------: | --------------------------------------------- |
| `ValidationEnabled`       | `bool`       |     `true`    | Toggle for mapping validation                 |
| `TraceEnabled`            | `bool`       |    `false`    | Toggle for diagnostic tracing                 |
| `TraceOutput`             | `TextWriter` | `Console.Out` | Destination for trace output                  |
| `MetricsEnabled`          | `bool`       |    `false`    | Toggle for performance metrics (enables `Interlocked` counters) |
| `MaxRecursionDepth`       | `int`        |      `64`     | Maximum recursion depth (prevents stack overflow from circular references) |
| `MaxInlineDepth`          | `int`        |      `5`      | Maximum inline depth for nested object expression trees |

> **Related APIs**:  
> `MaxRecursionDepthUpperBound` (= 4096) and `MaxInlineDepthUpperBound` (= 16) — constant upper bounds for recursion/inline depth settings (`public const int`; values assigned to `Mapper.MaxRecursionDepth` / `Mapper.MaxInlineDepth` exceeding these limits will be clamped). (Source anchor: `Mapper.cs:847/:879`)  
>   
> `TypeConvertHelper` — A generic type conversion utility class (used internally by the engine; supports `string` ↔ primitives, value-type conversions, enum conversions, nullable conversions, etc.). Public entry point: `ConvertValue<TSource, TTarget>`. Custom converter implementations may follow its pattern. (Source anchor: `TypeConvertHelper.cs:7/:23`)

### 4.4 Performance Metrics

```csharp
Mapper.MetricsEnabled = true;

// Execute mapping operations...

Console.WriteLine($"Total calls: {Mapper.TotalMapCalls}");        // Interlocked atomic increment
Console.WriteLine($"Cache hits: {Mapper.CacheHits}");             // Hits on source-generated paths
Console.WriteLine($"Runtime fallbacks: {Mapper.CompilationCount}"); // Calls falling back to runtime engine due to missing generated cache (only counts first actual compilation)

Mapper.ResetMetrics();  // Reset counters
```

> Setting `MetricsEnabled = false` (default) avoids `Interlocked` overhead. Enable only during diagnostics.

### 4.4.1 Cache and Generation-Layer Management

| Method | Description |
| --- | --- |
| `ClearCache()` | Clears all runtime caches (driven by registry: cascades 17 items via `CacheRegistry.ClearFull`). Note: Re-freezing applies only to type pairs not yet compiled; for test isolation of identical type pairs, use unwarmed scenarios or process-level isolation instead. |
| `ClearGenerated()` | Clears only registration entries in the Generated layer (4 entries prefixed `generated-*`). Generic static fields (e.g., `GeneratedCache<T,S>`) cannot be cleared uniformly at runtime; individual entries must be overwritten by calling `RegisterGenerated<TS,TT>(null)`. |
| `HasGenerated<TS,TT>()` | Checks whether a source generator has registered a mapping delegate for the specified type pair (queries dictionary cache; semantics consistent with `ClearGenerated`). Returns `true` if registered, `false` otherwise. |

### 4.5 AOT Compatibility Annotations

| API        | Annotation                              | Description               |
| :--------- | :-------------------------------------- | :------------------------ |
| Source-generator path | — (code generated at compile time) | AOT-friendly: full code generation at compile time (zero reflection, no dependency on runtime type metadata) |
| `Compose`  | `[RequiresDynamicCode]` + `[RequiresUnreferencedCode]` | AOT-compatible when using `RegisterGeneratedCompose`; falls back to runtime expression-tree path (AOT-incompatible) if unregistered |
| `Validate` | Parameterless `Validate()`: `[Experimental("NCMapper001")]` (API stability) | `Validate()` is AOT-compatible (uses generated validation results, zero reflection); `Validate(params Assembly[])` is annotated with `[RequiresDynamicCode]` + `[RequiresUnreferencedCode]` (relies on reflection-based assembly scanning, AOT-incompatible) |

> In production, prefer using `[MapFrom]` attributes exclusively with source generators to ensure AOT compatibility.

### 4.6 Mapping Pipeline

Pluggable post-mapping (`PostMap`) callbacks. When the pipeline is empty, a `volatile bool` check ensures zero overhead.

```csharp
Mapper.Pipeline
    .AddPostMap<UserEntity, UserDto>((src, dto) =>
    {
        dto.FormattedDate = src.CreatedAt.ToString("yyyy-MM-dd");
        dto.CreatedBy = "system";  // Audit fields set directly inside PostMap
    });

var dto = Mapper.Map<UserEntity, UserDto>(user);
// Execution order: core mapping → `Action` → `PostMap` (in reverse registration order)

// Note: This snippet is for demonstration only; the final `Clear()` is included solely for cleanup.
// In production code, `PostMap` registrations are global and process-scoped — register once and retain long-term.
// Do *not* clear after every call.
// For one-off transformations, prefer `Mapper.Map(src, action)` — its `Action` callback is automatically cleaned up per invocation.
// Mapper.Pipeline.Clear();  // Only required for test teardown or controlled-scoped cleanup
```

> `PostMap` callbacks are filtered by `(TSource, TTarget)` type pair and apply only to matching mappings.  
>  
> `PostMap` callbacks are compiled into a reverse-ordered array on first execution and cached; subsequent invocations iterate directly over the cached array — no repeated `ToArray()` allocations.

**Typical Use Cases** — The mapping pipeline is ideal for cross-cutting concerns shared across multiple mappings, avoiding duplication in individual `Action` callbacks:

| Scenario | Usage |
| -------- | ----- |
| Audit fields | Populate `CreatedBy` / `UpdatedAt` in `PostMap` |
| Permission-based data masking | Mask sensitive fields (e.g., phone numbers, ID numbers) in `PostMap` based on user role |
| Data formatting | Format `DateTime` as strings or monetary amounts in `PostMap` |
| Data enrichment | Populate DTO fields not present in the source entity (e.g., computed or related data) in `PostMap` |
| Latency monitoring | Log duration of individual mapping operations in `PostMap` |

> An empty pipeline incurs zero overhead thanks to a `volatile bool` check — it does not impact mapping performance for pipelines that remain unused. Enable only when cross-cutting behavior is needed.

### 4.7 Exception Hierarchy

NCMapper defines a two-tier exception hierarchy, both located in the `NCMapper` namespace:

| Exception Type              | Base Class                    | Triggering Scenarios                                                                                                                                                                                                 |
| --------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MapException`              | `InvalidOperationException`     | Runtime mapping errors (e.g., circular reference exceeding `MaxRecursionDepth`, failure of deep-copy full strategy, type conversion failure, resolution failure of `[Convert]` method references — static method missing / inaccessible / signature mismatch with T0–T3 templates, etc.; runtime counterparts of compile-time diagnostics NCMAP035/036/037) |
| `MapConfigurationException` | `MapException`                  | Configuration errors (e.g., DTO missing `[MapFrom]` attribute, Compose unable to locate primary source type, non-existent field referenced by `[MapProperty]`, etc.)                                              |

> **`MapException` and Serialization**: `MapException` does not implement `ISerializable` (lacks a serialization constructor); thus, exception objects are not automatically reconstructed across AppDomain or remote boundaries.

> **Unified Runtime Exception Wrapping**: Underlying exceptions from the runtime expression tree path (e.g., reflection exceptions, conversion exceptions) are uniformly wrapped into `MapException` instances (preserving the original `InnerException`). This ensures consistency with exception types thrown along the source generator path, preventing callers from missing exceptions when catching.

Diagnostic properties exposed by `MapException` (to aid troubleshooting):

| Property Name    | Type        | Description         |
| ---------------- | ----------- | ------------------- |
| `SourceType`     | `Type?`     | Source type involved in the mapping operation |
| `TargetType`     | `Type?`     | Target type involved in the mapping operation |
| `PropertyName`   | `string?`   | Name of the property that triggered the exception |

> Since `MapException` inherits from `InvalidOperationException`, existing `catch (InvalidOperationException)` blocks will still catch it. To distinguish configuration errors from runtime errors, catch `MapConfigurationException` separately.

```csharp
try
{
    var dto = Mapper.Map<UserEntity, UserDto>(user);
}
catch (MapConfigurationException ex)  // Configuration error (e.g., DTO missing [MapFrom])
{
    Console.WriteLine($"Configuration error: {ex.Message} [{ex.SourceType?.Name} → {ex.TargetType?.Name}]");
}
catch (MapException ex)               // Runtime mapping error
{
    Console.WriteLine($"Mapping failed: {ex.Message}, Property={ex.PropertyName}");
}
```

> **Bilingual Error Messages**: All exception messages and diagnostic texts are provided via the `ErrorMessages.cs` resource file in both Chinese and English. The appropriate language is automatically selected based on the current thread’s `CultureInfo`, requiring no user configuration.
